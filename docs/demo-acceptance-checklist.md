## 范围、环境与证据约定

目标是可独立重放、异常可恢复的招聘闭环 Demo：多文件导入 → 程序解析与人工补全 → 身份核对与投递复用 → 岗位匹配 Agent 分析与 HR 决策 → 测评发放与 HR 结论 → 笔试发放与 HR 结论 → 单轮或多轮面试 → Offer 审批发放与通知 → 候选人接受 → 入职办理 → HR 确认到岗。测评和笔试外链必填，试卷文件可选且内部留存；邮件只发链接；HR 手动选择通过／不通过／跳过并写备注。系统不建设答题、计分、阅卷或考试平台同步；邮件发出不代表已作答。外部能力以明确标注的 Mock 和可注入替身验收；本清单不授权真实邮件、模型、会议、日历或企业微信外呼。

- 仅使用独立验收配置、临时数据库、临时上传及导出目录和虚构个人资料。测试进程不得加载本地真实 `.env`、现有业务数据库、真实简历或生产密钥，也不得改写这些文件；保护检查只记录文件摘要或元数据，不输出内容。真实集成凭证不进入替身测试环境。
- 固定 12 份虚构简历和 2 份 JD，形成 24 个简历/JD 配对的人工基准；记录样本、JD、标注版本及审核人。两份 JD 必须具有不同的实际 `job_id`，不得仅凭岗位标题决定投递归属。
- 人工基准至少标注身份字段、履历事实、岗位要求、匹配证据、缺失信息、允许的分数区间和应有的排序关系。基准未由用户或指定 HR 确认时，相关验收保持未执行，不能由测试程序或 AI 自行宣布通过。
- 事实来源可包括原始简历和明确的人工修改记录。人工确认的新事实应引用修改人、时间、前后值和说明；不要求它必须出现在旧简历中，也不能把有记录的人工事实判成模型幻觉。旧原文和旧版本始终保留。
- 邮箱验收仅验证格式，不证明真实存在或可达；手机按实施方案的工程默认范围验证，并注明支持边界，不将默认范围表述成用户逐项指定。邮箱和电话均不通过真实发送或拨号验证。
- 每项记录使用“未执行 / 通过 / 失败 / 不适用”之一。默认未执行；不适用必须写明理由、批准人和范围，不能用来跳过 Demo 必需项。只有通过才勾选。
- 历史基线为 **53 项 Python 测试和 4 项主题测试**，仅用于回归参考，不是本轮执行结果，也不证明新功能、真实 AI 质量或外部联通已通过。
- I—K 及 S07—S09 已按 Q14—Q20 明确操作和预期。工程默认值见实施方案 3.6，测试代码在实施时按具体路由、字段和配置落地；本轮结果按下表与实施记录填写，不预填未执行的组合场景。不得把已撤销的在线答题、计分和阅卷要求重新算入本轮验收。
- 简历程序解析必须可在禁用模型调用时独立完成；复杂经历未识别应保留原文并提示核对，不能生成虚假完整结果。岗位匹配可读取该投递原文与已确认事实，但不能自动覆盖人工资料或推进招聘状态。
- 旧投递已处于面试、Offer 或已入职时保留原阶段，将新增前置环节标为历史未记录；不能伪造测评／笔试通过记录或强制倒退补发。新投递按 HR 通过／跳过推进，不通过终止当前投递。

建议每次执行记录：`运行编号、代码版本、配置版本、数据集版本、执行人、北京时间、验收 ID、结果、实际结果、证据路径、缺陷编号、复验编号`。证据包括测试输出、脱敏数据库断言、请求/响应、页面截图和审计事件；截图不能单独证明数据库约束、并发安全或持久化。

## 主 Agent、脚本与人工复核

| 工作 | 默认方式 | 验收边界 |
|---|---|---|
| 设计断言、实现功能、修复缺陷和汇总结果 | 主 Agent | 用已确认业务规则定义预期，不能把当前实现输出直接抄成正确答案 |
| 语法／回归、接口状态、数据库约束、解析、资源管理、邮件故障、幂等和重启 | 可重复脚本 | 保存输入、输出、退出码、证据与版本；优先复用现有测试入口，不为每项创建一个孤立脚本 |
| 生成虚构样例、校验标注结构、比较结果和汇总报告 | 脚本辅助 | 样例是否有代表性、引用是否支持判断不能仅靠格式校验决定 |
| 岗位匹配语义质量、人工标注、流程推进、办理完成条件 | 用户／指定 HR 确认，主 Agent 辅助 | 公司考试题目与阅卷不由本系统实现；发送结果和考试结论不能混为一谈，业务判断不能由测试脚本自批 |
| 跨阶段状态、历史迁移、权限边界中确需第二视角的问题 | 按需一个只读子 Agent | 记录具体问题、审查依据、发现及主 Agent 处置；不要求每阶段都启动，也不以“多 Agent 都同意”替代验证 |

独立审查不承担常规测试执行和批量样例生成，也不直接改业务文件。未启动子 Agent 不属于验收缺项；若审查发现具体缺陷，仍须复现、修复并补充相应程序证据。
